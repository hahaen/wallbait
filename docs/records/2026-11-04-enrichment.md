# 2026-11-04：残骸布局、精彩操作与芯片支线

本轮固定起点 `84471267714fc136c0b9738f91109cde75e6ea66`，原始工作区 `main`、暂存区与未跟踪文件均干净，交付目标 `origin/main`。用户授权完成三个方向、按规范评审验证并提交推送，明确暂不部署。

## 本轮规格与实施

- 保留四章 20 关、三类追逐者、一至三敌和两个技能；不添加薄墙、数值成长、后端或联网功能。
- 第 8 关保留残骸入门；第 11、18 关改为中央 T 口与右侧绕道。中央撞毁能提供下次诱撞点，同时堵住中央口，仍可选择右侧路线。主要选择是第一只的撞毁位置、解决顺序及是否提前取芯片，不强制唯一解。
- 精彩操作：借尸筑墙（撞实心残骸）、一标双骗（同一枚信标正式锁向后两敌撞毁）、脚下留电（零闪避通关）、擦肩而过（正式蓄力最后 160ms 内从危险通道走出，且避过该次冲刺）。每局每种一次，不增加星级或战斗属性。
- 局内在地图外单独显示短反馈，危险提示保持独立；反馈随规则时间暂停，3 秒消退。胜利结算列出本局称号，选关档案累计通关获得的称号。
- 第 7、11、18 关各一枚可选芯片，普通移动及闪避逐格拾取；接触敌头失败的格不收集，信标与敌人不代取。拾取不影响胜负或星级，带出通关后保存；失败、重开没有本局携带状态。
- 芯片解锁三段阿零的试验场记忆，在选关页阅读。旧版 v2 成绩与设置保留，新字段缺失按空集合；损坏、未知编号和无通关成绩的收藏不导入。失败不写收藏，重玩不倒退收藏，存储不可用保留内存并沿用警告。

远端同步曾出现认证阻塞：HTTPS 没有可用凭据，SSH 多次返回 `Permission denied (publickey)`。随后核对 GitHub 公开登记公钥与本机默认公钥指纹一致，同一密钥、同一配置重试返回 `Hi hahaen!`，说明当前密钥有效；此前将其判断为缺少可用 GitHub 密钥过早。当前连接经过 Quantumult X 2 的 `utun4` 隧道，标准 22 端口握手被关闭，443 认证有先拒绝、后成功现象；现有日志不足以唯一定位隧道通道还是 GitHub 端的临时状态。

最终使用公开 DNS 返回地址建立临时 SSH 连接，保留官方主机密钥校验并复用连接，成功获取同一 `origin/main`。获取后 `HEAD...origin/main` 为 `0 / 0`，没有新增远端提交，无需合并或恢复未提交改动。没有修改系统 VPN、DNS、SSH 配置或认证凭据；临时连接在交付后关闭。游戏规则、测试和图片与已验证备份一致，仅本记录补充认证诊断。提交与推送结果在最终交付说明报告。

芯片回放从正常出生只发送玩家命令：第 7 关 2.44 秒、第 11 关 9.84 秒、第 18 关 5.48 秒。第 11 关先取芯片、通过待生效中央口、从右侧引敌绕回；第 18 关三敌错峰借中央残骸接力。主线另外保留不要求收芯片的解，证明支线不强制。

自动搜索最初只找到场边接力，未据此宣称中央设计成立。最终芯片方案使用正常走位前奏配合搜索，并以实际撞击坐标验证中央残骸，不修改对局状态；生成与回放采用同一核心。搜索宽度与前奏只是测试工具，不是游戏内引导或难度证明。

浏览器首轮第 18 关在携带芯片后暂停，再继续固定 120ms 时间表时未按预期结束。暂停按既有设计清空渲染帧余量，不能把中断前后的帧相位当作连续精确回放。用例改为先验证携带时暂停冻结与重试清空，再从正常出生连续执行同一命令方案；第 18 关独立复验通过，游戏规则未调整。随后重跑全套浏览器验证，47 项通过 / 4 项按配置跳过（非桌面的完整键盘旅程两项、WebKit 不支持的 Chromium CDP 两项）。本机通过不代表实体手机或远端 CI 已验收，未确认远端 Actions 结果。
