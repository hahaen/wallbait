# 豆豆角色、受挫反馈与手机摇杆

起点为`main` / `d36ef942d1ecf254223e9da5f5dbd65452a21d34`，工作区与暂存区干净。用户要求优化小虫子、苹果、被追上的效果和手机按钮，随后强调必须保留豆豆分节，并反复明确要软萌的造型。本轮直接在原交付工作区修改，目标仍为`origin/main`，不部署。

## 最终实现

- 用内置imagegen重新制作暖色手绘透明角色图集，取代被用户否定的程序圆形和瞪眼造型。嫩绿、奶黄、浅紫三类小虫子保留一颗颗饱满豆豆，搭配大脑袋、小眼睛、腮红、小刘海与笑脸。首页、说明、对局和结算共用素材；[原图、帧表及最终提示词](../design/bean-mascots.md)可复核。
- 受挫时苹果短暂挤压、小跳、微倾与少量碎光，蛇换开心表情，苹果为无受伤表现的懊恼表情。默认画面不再叠命中编号、路线方框和红圈；只有用户主动进入“查看失败现场”才显示诊断。保留1200ms现场停留和减少动态效果支持。
- 左手一体摇杆、右手大工具按钮，信标固定在工具上方。摇杆144–164px、方向热区52px，主工具最低108×104px，信标最低108×48px。18%死区和1.18倍转向滞回抑制斜向抖动，拖出外圈可继续移动；松手、取消、重置、尺寸变化和销毁均释放输入。支持双指移动加工具，也保留方向点按和键盘。
- 可用工具只显示图标与名称，等待、冷却和阻挡时才显示短提示。图集加载失败时保持冻结并提供重载入口，不允许角色缺失的空白开局。

渲染仅更新贴图帧、位置和大小，不改写core坐标、碰撞、敌人时序、胜负、关卡或存档格式。图集在场景加载时创建纹理和帧，逐帧复用。未新增运行依赖或服务。

## 评审与必要验证

每次修改先自审规格、边界和差异，再执行验证；修正过样式选择器误匹配和主动查看现场时诊断层被角色遮挡，复核新贴图加载失败、终局插值与输入释放，没有遗留发现。没有另行调用代理评审或声称外部人工验收。

- `npm run check`通过：ESLint、Prettier、136项规则/输入/存档/回放测试、严格类型检查和生产构建。
- 最终完整浏览器回归100项通过、5项按配置跳过（WebKit的Chromium CDP专属用例）；覆盖桌面/手机尺寸Chromium及手机尺寸WebKit、连续20关、全部流程、输入和资源失败恢复。
- 复查并调整主动查看现场的图层后，重新通过`npm run check`及14项相关浏览器专项（1项CDP专属用例按配置跳过），覆盖查看/返回/重试、输入、资源失败与三个浏览器项目。
- `/wallbait/`真实生产包最终连续3/3通过，新PNG资源、首页、开局、通关与恢复正常。复验曾暴露旧脚本的低频断言轮询会错过短冲刺，已改为逐帧观察、先发操作再截图，并完成三次连续稳定性验证。
- 最终素材前的旧图验证和一次为更换美术而中断的回归不计入最终图集验收；最终代码另行重跑。

### 小米14真机

通过ADB连接Xiaomi14（23127PN0CC）的实体Android Chrome，原生视口400×789、DPR3，没有改视口、时钟或规则状态。通过CDP发送真实触摸事件，控件夹具确认`isTrusted`及`pointerType=touch`，覆盖死区、斜向稳定、拖出外圈、双指技能、松手、取消和清理。夹具不冒充完整游戏；另在真实对局双指横向闪避通过第一关，完成下一关暂停冻结。脚本先修正触摸回传等待和暂停按钮定位，最终整轮重跑通过。

实测摇杆164×164px，工具116×112px；地图与两个控件互不重叠。失败到结算观察为1292ms，页面脚本错误0。当前留下暂停的第二关，USB本地端口反向映射保留以供试玩。
