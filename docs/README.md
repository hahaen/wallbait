## 维护约定

本机交互抽样与回归见[2026-11-04 补验记录](testing/followup-2026-11-04.md)，后续未验收项见[进阶版后续事项](remaining-work.md)。

1. 开发前阅读项目开发约定、已有的玩法与架构文档，以及相关模块 README。
2. 开发时在对应模块目录补充设计、接口约定和重要实现说明；简单功能直接更新模块 README，内容较多再按主题新增 Markdown 文件，并补上链接。
3. 行为、参数或模块边界变化时，同步更新整体文档，避免把同一规则复制到多处后各自修改。
4. 完成功能或修复后，在 `records/` 记录变更、验证结果和遗留事项；详细验收证据放在 `testing/` 并互相链接。
5. 明确区分“计划”“已实现”“已验证”；未执行的测试写明未执行，不将目录、文档或效果图计为玩法完成。
6. 文档不保存凭据、验证码或其他敏感数据。新增文档使用相对链接，并从本导航或所属目录 README 提供入口。
