# 简单策略专项验收

日期：2026-11-04。命令：`GENERATE_STRATEGIES=1 npx vitest run tests/strategies.test.ts`。7 项通过，覆盖 20 关 × 7 种策略，共 140 个回合。

每回合从 `createState(level)` 的正常出生开始，使用 20ms 固定步，只向 `step` 发送方向、闪避和信标命令。策略不修改坐标、敌人、机关、计时或胜负。每个回合在胜利、失败或 60 秒时停止；“超时”表示仍未通关，不能当作死亡。

策略源码见 [strategies.ts](../../tests/strategies.ts)，全部数值结果见 [strategies.json](../../tests/fixtures/strategies.json)。默认 `npm test` 会重新执行算法，并与保存结果逐项对比，避免规则改变后继续引用旧报告。显式生成时即使门槛失败，也会保存实际报告。

## 固定算法

- **原地等待**：从出生起不发送方向或技能，最多观察 60 秒。
- **左手贴墙**：先向左直到遇到墙或关闭门，再朝上沿左手墙行走。每到新格按左转、直行、右转、掉头顺序选可行方向；不读取敌人，不用技能。
- **右手贴墙**：先向右直到遇到墙或关闭门，再朝上沿右手墙行走。每到新格按右转、直行、左转、掉头顺序选可行方向；不读取敌人，不用技能。
- **固定矩形绕圈**：按上 1200ms、右 960ms、下 1200ms、左 960ms 无限循环，形成 8×10 格矩形；撞障碍仍按既定时间换向，不读取敌人或机关。
- **无脑重复闪避**：沿固定矩形的时间表移动，每 240ms 尝试闪避，不检查资源或敌人；是否执行由正常规则决定。
- **首次预警只横移一次**：原地等第一条正式预警，优先沿锁向顺时针垂直方向侧移一格；被墙挡则选反方向，两个方向都被挡则继续尝试。成功移动后一直不动。
- **盲放信标加绕圈**：沿固定矩形的时间表移动，每 240ms 原地尝试放信标，不看敌人、墙距、资源或已有信标；禁用和费用限制由正常规则决定。

- **第 11—20 关**：本次七种固定算法均未通关。这个结果只证明这些具体算法未奏效，不能推出没有其他简单解，也不能替代实际试玩对操作手感和合理难度的判断。

## 超时与失败解释

不操作时，第 3、4、6、7、10、12、20 关在 60 秒时仍有敌人。关闭门提供安全准备区；截击者的预测落点、侦察者的刹车距离也可能允许玩家暂时站住。这些是“活着但没有完成目标”，并非系统强迫等待。玩家仍可立即移动、踩踏板或放信标主动推进。

左右贴墙在第 4、6、10、12 关全部超时，门切换次数均为 0，剩余敌人数分别是 1、2、2、2。这证明沿当前房间的墙走不会自动打开踏板门；也说明这部分结果主要检验机关参与要求，不能单凭它认定开门后的战斗有挑战。

固定矩形和盲信标在第 6 关未踩开门，60 秒后均余 2 个敌人。第 16 关单次侧移淘汰了下室的 1 个敌人，但余下 2 个敌人和门未处理。第 20 关盲信标投放 21 次、淘汰 1 个敌人，仍余 2 个，门切换 0 次，说明重复消耗资源无法替代进入下一室的决策。

其他失败由真实头部碰撞或留在锁定冲刺通道内触发；每个回合的具体失败文字、剩余敌人、用时、技能次数、移动格数和门切换次数都保存在 JSON 中。

## 证据范围

本专项是可复现的规则模拟，不是人类试玩或真机触控测试。固定矩形只覆盖一个尺寸和相位，贴墙策略只覆盖两种手性，未穷举所有路线、预先开门后的套路、信标周期或策略参数。必须结合 20 关获胜回放、真实浏览器试玩和输入验收判断整体质量。
