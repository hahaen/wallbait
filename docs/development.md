## 日常开发

1. 先读取 `AGENTS.md` 和相关模块 README。
2. 开发规则时先确定输入、状态、事件和碰撞顺序，随后接入表现。
3. 一个功能连同其验收和必要测试完成后，再进入下一个功能。
4. 提交前运行 `npm run check`；首次加入测试后将测试也纳入该命令。
5. 按实际情况更新里程碑，不把文档、占位页计为已实现的玩法。

当前工程不需要环境变量或第三方 API 密钥。
依赖安装使用 `npm ci`；新增依赖用 `npm install` 并一起提交锁文件。
项目 `.npmrc` 使用 npm 官方源，避免公开锁文件绑定个人配置的镜像地址。

## 关键验收

| 项目 | 通过标准                                             |
| ---- | ---------------------------------------------------- |
| 移动 | 按住持续移动，松开停下；不斜走、不穿墙               |
| 预警 | 玩家能明确辨认方向，蓄力后方向不悄悄改变             |
| 冲刺 | 冲刺阶段不转弯、不穿透苹果或墙                       |
| 闪避 | 距离和冷却一致，不可穿墙、不可冷却中重复使用         |
| 胜负 | 撞墙胜利、被蛇头碰到失败，同一步冲突结果稳定         |
| 暂停 | 逻辑时间和冷却冻结，恢复无补帧突进或残留输入         |
| 触屏 | 移动和闪避可同时按；取消触控不会持续移动             |
| 布局 | 常见手机竖屏下地图和按钮可见，无安全区遮挡；桌面居中 |
| 重开 | 坐标、蛇阶段、计时和冷却重置，监听器不重复绑定       |
| 存档 | 刷新保留设置和统计，存储失败时仍可游玩               |

构建和类型检查只能证明工程可编译，不能证明手机手感或规则正确。

## GitHub Pages 预留方案

后续从 `main` 构建，使用 GitHub Actions 上传 `dist/` 并部署 Pages。
预计项目路径为 `/wallbait/`；当前 Vite `base: './'` 支持相对静态资源。
首版不引入 history 路由，避免刷新子路径产生额外配置。

真正发布时再添加所需的 `pages: write`、`id-token: write` 权限与 Pages environment，
保持日常 CI 仅拥有读取源码权限。发布前后都验证资源路径、手机显示和暂停行为。
