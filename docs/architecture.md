# 架构设计

## 目标

首版用一个纯前端工程验证反向贪吃蛇的手感。规则可以在不启动浏览器的情况下测试；
调整速度、预警时间、闪避距离时不需要修改绘图代码。

当前只有启动场景；以下是后续开发遵循的边界，不是已经完成的模块清单。

## 模块依赖

```text
main.ts → game/createGame.ts → scenes
                                 ├── input → 玩家命令
                                 ├── core  → 状态与事件
                                 ├── ui    → 显示状态、发出命令
                                 └── storage → 设置与统计

core → 只依赖自己的类型、配置和规则
```

场景负责组装与生命周期管理。输入不直接改角色坐标；UI 不直接更改冷却或判定胜负。
存储不参与逐帧运算，只在设置改变、结算等边界读写。

| 模块              | 后续主要文件                                                    | 职责                                     |
| ----------------- | --------------------------------------------------------------- | ---------------------------------------- |
| `core/`           | `types.ts`、`config.ts`、`state.ts`、`step.ts`                  | 状态定义、难度参数、初始化和统一逻辑入口 |
| `core/systems/`   | `movement.ts`、`snake.ts`、`collision.ts`、`dodge.ts`           | 苹果移动、蛇状态机、逐格碰撞、闪避规则   |
| `game/scenes/`    | `BootstrapScene.ts`、`PlayScene.ts`                             | 资源启动、对局生命周期                   |
| `game/renderers/` | `ArenaRenderer.ts`、`AppleRenderer.ts`、`SnakeRenderer.ts`      | 将逻辑状态画出来，处理位移插值和反馈     |
| `input/`          | `commands.ts`、`keyboard.ts`、`touch.ts`                        | 将按键和多点触控转换为相同命令           |
| `ui/`             | `Hud.ts`、`TouchControls.ts`、`PausePanel.ts`、`ResultPanel.ts` | 冷却、操作、暂停和结果显示               |
| `storage/`        | `save.ts`                                                       | 存档版本、校验、默认值和迁移             |

这些文件按对应功能实际开发时创建，避免空实现。首版暂停和结算可使用覆盖面板，
不必为了每个面板创建单独场景。

## 逻辑状态和时间

拟采用以下数据结构方向：

- `GameState`：对局阶段、地图、苹果、蛇、对局用时和结果。
- `AppleState`：格坐标、朝向、移动计时、闪避冷却。
- `SnakeState`：身体格列表、朝向、行为阶段、阶段计时、锁定冲刺方向。
- `PlayerCommand`：移动方向改变、闪避、暂停、继续、重新开始。
- `GameEvent`：蓄力开始、冲刺开始、闪避成功、碰撞、结算等一次性表现事件。

使用固定逻辑时间步，建议初值 50ms；渲染使用 Phaser 的逐帧更新。
移动速度以“每格耗时”配置，不在每一帧无条件走一格。
画面位置在前后两次逻辑位置之间插值，逻辑坐标始终为整数。

场景将帧间隔累积到逻辑时钟，限制每帧最大补算次数，避免卡顿后无限追帧。
页面进入后台立即暂停、清空输入与累积时间；返回后等待玩家主动继续。
冷却、状态机和对局时间全部依赖逻辑时间，不使用 `setTimeout` 或墙上时钟推进。

## 一步中的处理顺序

推荐实现次序：消费命令 → 苹果移动/闪避 → 更新蛇阶段与位移 → 结算事件。
最终顺序须在规则实现时通过测试固定，并同步玩法设计。

位移不能只检查终点：蛇冲刺和苹果闪避需逐格检查路径，处理头部相遇与换位穿越。
碰撞发生后立即锁定结果，后续子步骤不再更改结局。
同一时刻的冲突暂定“蛇头触及苹果优先判负”；此前已经触墙结束的对局不再处理后续移动。

## 资源和坐标

- 逻辑：地图左上角为 `(0, 0)`，x 向右、y 向下；墙外不属于可通行格。
- 画面：竖屏设计尺寸暂用 390 × 844，Phaser FIT 等比缩放，桌面居中显示。
- 地图尺寸与画面尺寸分开；渲染器负责格坐标到像素坐标的换算。
- `src/assets/` 放打包资源；`public/` 放固定地址的公开文件。
- 不在逻辑中保存 Phaser 对象，不让动画完成回调决定规则是否生效。

## 工具选择

- Phaser 先固定在 3.x 系列，升级大版本单独验证，不随安装默认跳到 4.x。
- TypeScript 使用 6.0.x，与当前 typescript-eslint 的支持范围一致。
- Node.js 统一 24.x，npm 使用锁文件；CI 通过 `npm ci` 重现依赖。
- 不提前引入物理引擎、ECS、全局状态库、React/Vue、后端或联网服务。
- 核心规则开始实现时再添加 Vitest，并将规则测试纳入 `npm run check`。

官方参考：[Phaser 3 文档](https://docs.phaser.io/)、[Vite 指南](https://vite.dev/guide/)。
