# 架构设计

Phaser 3 + TypeScript 严格模式 + Vite。纯前端，不增加 UI 框架、物理引擎、通用 ECS 或后端。

## 模块边界

- `src/core/types.ts`：整数坐标、关卡与门配置、输入命令、规则状态和一次性事件。
- `src/core/config.ts`：毫秒时间、移动与共享电量参数、三类敌人基础参数。
- `src/core/engine.ts`：创建状态、20ms 固定步、目标选择、BFS 追踪、锁向冲刺、逐格碰撞、门切换、信标、电量、暂停与星级。没有 Phaser、DOM 或存储依赖。
- `src/core/levels.ts`：四章 20 关数据，包含设计意图、主要决策、失败原因及配置合法性检查。
- `src/game/`：Phaser 组装、规则驱动、绘制、插值与反馈。
- `src/input/`：键盘和多指 Pointer Events 转成命令，不写角色坐标。
- `src/ui/`：首页、选关、HUD、操作区与弹窗；发出操作并在结算边界记录成绩。
- `src/storage/`：版本与关卡集隔离的存档读写、旧版迁移和异常回退。

内部保留 `apple`、`snakes`、`SnakeKind` 等已有字段名以保持边界接口稳定；产品角色分别是机器人阿零和机械追逐者，字段名不代表继续使用旧版美术或规则。

## 时间、命令与碰撞

`step(state, command)` 只推进 20ms，命令为四向/停止、闪避和信标意图。画面累计帧间隔，每帧最多补五步；暂停清空累积时间与输入。动画不决定规则，所有碰撞只读取整数格。

一步处理：清空旧事件 → 冻结检查 → 时间、短锁、回充、信标到期 → 可生效的门请求 → 朝向及初始碰撞 → 逐格闪避 → 放信标 → 普通移动 → 各敌人状态与逐格冲刺 → 头部命中优先判负 → 全部淘汰判胜 → 对局仍进行时处理门请求。玩家经过敌人当前头部立即判负，不能交换位置穿越。终结状态不再推进或重复结算。

`solid(level, point)` 只检查静态墙；`blocked(state, point)` 同时检查当前关闭的门，待执行状态不参与碰撞。追踪、视线、玩家移动、冲刺与渲染预警共用实际地形，避免画面和规则出现两套门状态。

## 目标、信标与门

`targetFor` 仅用于追踪与观察。普通敌人追当前玩家，截击者追朝向前两格的预测点；信标存在时统一改追信标。侦察者对真人保持路径距离，并拒绝会撞墙的冲刺，对信标取消这项安全判断。BFS 距离场按目标缓存于单步内；不可达或位于关闭门内的目标不会产生穿门路径。

进入 `charging` 时固定 `locked`，之后只沿该方向逐格冲刺。`warningPath` 输出当前剩余的可通行危险格，供画面使用。玩家改变朝向、信标出现或到期都不重定向已锁定攻击。

门定义保存在关卡，`GameState.gates` 保存当前开闭与可空的待执行目标。玩家从同组踏板外进入触发翻转；再次触发可以取消待执行请求。所有预警/冲刺结束前门状态冻结；关门时角色占用则继续等待，防止改变已展示路径或夹伤。

电量上限两格，两个技能各耗一格。`rechargeMs` 为累计回充进度，HUD 用 `RECHARGE_MS - rechargeMs` 显示距离恢复时间；`cooldownMs` 仅表示闪避的 240ms 短锁。信标有独立剩余寿命，暂停统一冻结这些规则时间。

## 存档隔离

v2 写入 `wallbait.save.v2`，要求 `version: 2` 和 `campaign: 'foundry-v2'`。旧 v1 键仅只读，保留原文；迁移设置与历史通关数量，新关卡重新记录成绩和解锁。用时、闪避、信标和星级各自保存最优值，解锁进度由连续通关记录恢复。读取每个键独立捕获异常，访问 `localStorage` 本身也处于惰性边界内。

## 验证与构建边界

Vitest 覆盖核心规则、输入之外的存档边界以及保存的关卡命令回放。搜索器只在显式生成时执行，复制独立候选状态并仅调用 `step` 发送命令；正常验收直接重放文件，不运行搜索。关卡合法性包括静态连通、出生、门配置和机关区域可达性，但不代替含敌人时序的实际通关证明。

Playwright 验证完整流程、浏览器尺寸、触控与生产包子路径；自动回放证明可解，实际试玩用于判断难度与手感，两者分开记录。手机尺寸浏览器结果不等同真机结果。Node.js 24.x，按锁文件安装；资源使用相对路径，无 history 路由，需检查 `/wallbait/` 加载。CI 只检查，不发布。当前执行结果以[验收文档](testing/README.md)为准。
